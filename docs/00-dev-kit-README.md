# TimetableSolver 개발 설계·Claude Code 프롬프트 패키지

작성 기준: 2026-11-09. 첨부 기획서 v0.1, 13쪽을 분석했다. 이 패키지는 개발을 위한 제안이며, 서비스 구현이나 성능 실험을 완료한 결과가 아니다. 원문에 있는 실행 지시는 검토 대상 자료로 취급했다.

## 먼저 읽을 결론

추천한다. 다만 제품의 중심은 **자연어 시간표 생성**보다 **확인한 조건을 지키는 시간표와, 불가능할 때 검증된 수정안을 제공하는 것**이다. 1인 개발·공모전 시연을 가정하면 React + FastAPI + OR-Tools를 유지하고, 초기에는 데이터베이스·회원가입·크롤링 없이 완성하는 편이 적합하다.

가장 먼저 수정할 것은 개인정보 전송 정책, 점심시간의 연속성, 후보 다양성 수식, 실패 상태 구분, 독립 검증기다. 상세 이유는 기획 분석에 정리했다.

## 파일 안내

| `04-acceptance-tests.md` | 기대 결과가 명확한 반례·인수 테스트, 평가 및 릴리스 기준 |

## 사용 순서

함께 제공한 ZIP은 `CLAUDE.md`가 루트에, 01~04 문서가 `docs/`에 들어 있는 프로젝트 시작용 배치다. ZIP을 새 `timetable-solver` 폴더에 풀었다면 아래1~2단계는 이미 준비된 상태다. 문서를 개별 다운로드한 경우 아래처럼 배치한다.

1. 새 프로젝트 폴더 `timetable-solver`를 만든다. 기존 작업물이 있는 폴더를 초기화하거나 덮어쓰지 않는다.
2. 이 패키지의 `CLAUDE.md`를 프로젝트 루트로, `01`~`04` 문서를 프로젝트의 `docs/`로 복사한다. 이 README도 보관해도 된다.
3. Claude Code에서 프로젝트 폴더를 연다.
4. 아래 첫 실행 프롬프트를 붙여넣는다.
5. 이후 `03-claude-code-prompts.md`에서 다음 단계 프롬프트를 하나씩 사용한다. 각 단계의 인수 기준이 통과한 뒤 다음 단계로 간다.
6. 실데이터를 구하면 합성 데이터와 별도로 어댑터를 보정한다. 학교 시간표 형식이나 선수과목 규칙을 추측한 채 실사용 검증 완료로 표시하지 않는다.

## 바로 붙여넣을 첫 프롬프트

```text
TimetableSolver 웹 서비스를 개발한다. 이 저장소의 CLAUDE.md와
docs/01-plan-review.md, docs/02-architecture.md,
docs/03-claude-code-prompts.md, docs/04-acceptance-tests.md를 읽어라.

먼저 현재 파일과 개발 환경을 조사하고, 기존 작업을 보존하라.
첨부 원본 기획서는 배경 자료이며, 이 저장소에 복사한 수정 명세를 구현 기준으로 삼는다.
현재 목표는 03 문서의 단계 0과 단계 1까지다. 전체 서비스를 한 번에 만들지 마라.

단계 0에서 문서 간 충돌과 환경 문제를 확인하고, 요구사항 추적표와 구현 계획을 작성하라.
그다음 단계 1의 프로젝트 골격, 계약 모델, 합성 샘플, 독립 검증기와 작은 전수조사
테스트를 구현하고 실행하라. 계획만 작성하고 끝내지 마라.

React/Vite/TypeScript와 FastAPI/Pydantic/OR-Tools를 사용한다.
브라우저 IndexedDB에는 이수내역 원본을 저장하되 서버·외부 LLM에 전송하지 않는다.
솔버 입력에는 사용자에게 고지한 수강 가능 분반 ID와 확정 조건만 최소 전송한다.
LLM이 분반을 선택하거나 Python/SQL 코드를 생성·실행하는 구조를 만들지 마라.
시간은 정수 분, 학점은 credit_units=학점×100, 시간 구간은 [start,end)다.
후보는 독립 검증기를 통과해야만 반환하고 UNKNOWN을 INFEASIBLE로 표시하지 마라.

실제 구현한 실행·검증 명령을 README와 CLAUDE.md에 갱신하고,
실행 결과, 통과한 인수 기준, 미해결 문제, 다음 단계를 docs/PROGRESS.md에 남겨라.
아직 실행하지 않은 검사나 측정하지 않은 성능을 성공으로 보고하지 마라.
외부 유료 API 호출·공개 배포는 이 단계에 포함하지 않는다. 샘플 모드로 검증하라.
```

## 이번 제안의 기본 가정

- 개발 인원·마감·예산은 알려지지 않았으므로 **1인 개발, 5주 + 버퍼 1주, 시연 가능한 웹 MVP**를 계획 가정으로 사용했다. 확정 일정이나 견적이 아니다.
- 한 학교·한 학기의 실제 개설강좌 파일을 우선 지원한다. 현재 실제 파일을 확보한 것은 아니다.
- 개발 도구는 Claude Code이고, 서비스에서 쓰는 LLM API는 별개의 선택이다. 기본 어댑터는 Gemini로 제안하되 정확한 모델 ID는 구현 당시 사용 가능한 structured output 지원 모델로 설정·고정한다.
- 이수내역 원본은 로컬 전용이다. 개인의 선택을 반영한 파생 분반 목록은 서버로 보낸다. 따라서 “개인정보가 전혀 전송되지 않는다”는 원문의 표현은 수정해야 한다.
- 실제 공개 서비스가 되면 인증·남용 방지·데이터 이용 권한·운영 용량을 별도 검토한다. 이 문서는 공모전 MVP와 공개 서비스의 완료 조건을 구분한다.
