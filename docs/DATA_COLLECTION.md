# 데이터 수집 계획 (Phase C)

원칙: 배포(B14–B17)는 보류. 로컬 개발 기준. LLM은 **Gemini API**.
실데이터가 늦어져도 구현이 막히지 않게 **합성 데이터 먼저, 실데이터는 어댑터로 나중에 추가**.

## 1. 역할 분담

| ID | 작업 | 담당 | 비고 |
|---|---|---|---|
| C0 | Gemini 설정 반영 | Claude Code | `.env.example`, `config.py`, ADR 0004 |
| C1 | 데이터 요구사항 표 | Claude Code | `data/README.md` |
| C2 | 한동 개설강좌 확보 | **사용자** | 수강신청 화면에서 직접 복사/다운로드. 크롤링·로그인 자동화 금지 |
| C3 | 학사 규칙 | **사용자** + CC | CC가 빈칸 템플릿 생성 → 사용자가 채움 |
| C4 | 이수내역 샘플 | **사용자** | 이름·학번·성적 제거 후 형식만 |
| C5 | 스키마 확정 | Claude Code | C2·C4 확보 후 |
| C6 | 합성 카탈로그 생성기 | Claude Code | 즉시 시작 가능, D의 입력 |
| C7 | 불가능 시나리오 세트 | Claude Code | 5종 이상, 기대 충돌 집합 포함 |
| C8 | 선호 문장 수집 | **사용자** + CC | CC: 설문 문안·동의문·수집 템플릿·시드 문장 40개. 사용자: 지인 5–8명 배포 |
| C9 | 사전 설문 | **사용자** + CC | C8 폼에 문항 포함 |
| C10 | 정답 라벨링 | CC 초안 → **사용자 검수** | 정답은 사람이 확정. 20% 재라벨링 |
| C11 | 데이터 카드 | Claude Code | 파일 해시 포함 |

## 2. 순서

1. **Claude Code 1차 (바로 실행)**: C0, C1, C3 템플릿, C6, C7, C8 문안/템플릿, C10 가이드·검증기·시드 라벨, C11 초안. → 실데이터 없이 D 시작 가능.
2. **사용자 병행**: C2, C4 확보, C3 채우기, C8 설문 배포.
3. **Claude Code 2차**: C2·C4 파일이 `data/private/`에 들어오면 C5(스키마 수정)·실데이터 어댑터·파서 명세 작성.
4. 수집된 선호 문장이 오면 C10 라벨링 → 사용자 검수 → 게이트 GC.

## 3. 사용자 체크리스트

- [ ] Gemini API 키 발급 → `backend/.env`의 `LLM_API_KEY` (커밋 금지)
- [ ] C2: 개설강좌 원본을 `data/private/raw/`에 저장 (xlsx/csv/복사 텍스트 무엇이든). 학교 정책상 개인 개발·평가 용도 사용 가능한지 확인
- [ ] C4: 이수내역 붙여넣기 원문을 `data/private/transcript_sample.txt`에 저장 (이름·학번·성적 마스킹은 CC가 도와줄 수 있으나 **원문 자체는 커밋하지 않음**)
- [ ] C3: `docs/academic_rules.md` 빈칸 채우기 (학점 상한/하한, 시간 체계, 카테고리 체계)
- [ ] C8: 설문 문안 확인 후 지인에게 배포. 응답은 `data/private/survey_raw/`

## 4. 게이트 GC

1. 로더 입력 형식 확정 (실데이터 또는 "합성만" 명시)
2. 합성 카탈로그 3종(50/200/500) + 불가능 시나리오 ≥5
3. 선호 문장 + 정답 JSON (시드 40개로 시작, 목표 100)
4. 스키마 변경이 `docs/API.md`·코드·`openapi.json`·`api.d.ts`에 반영

## 5. 위험

- 실데이터 미확보 → 합성만으로 진행, 문서·발표에 "실데이터 검증 없음" 명시
- 정답 라벨을 LLM이 만들면 평가 오염 → 사람 검수 필수, 시드 라벨은 `source: author` 표기해 평가셋과 분리
- 공개 저장소 → 설문 원문·이수내역·강좌 원본 커밋 금지 (`.gitignore`로 막혀 있으나 커밋 전 `git status` 확인)
