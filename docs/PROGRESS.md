## 4. Gemini live

- `.env`: `LLM_PROVIDER=gemini`, `LLM_MODEL=gemini-3.5-flash-lite`, 키 설정됨(값 미출력). 모델 메타데이터 200, 가격 페이지 기준 무료 등급 존재(무료 등급 데이터는 제품 개선에 사용). 실제 결제 등급은 확인 불가. 다른 모델로 전환하지 않음.
- **호출 집계(정정)** — 사용자 키로 Google에 보낸 요청은 총 **7회**:
  - 생성(Interactions) **5회**, 모두 200, 재시도 0(개발 백엔드 로그 `v1beta/interactions` 5줄):
    - 1~4회: 합성 샘플 카탈로그 해석 검증(첫 번째 "실제 학교 데이터와 Gemini 연결 검증" 요청 처리 중, 호출 상한 지시 이전).
    - 5회: 실제 학교 데이터 흐름(두 번째 요청의 "재시도 포함 최대 5회" 상한 중 **1회** 사용).
  - 메타데이터 조회 **2회**(모델 정보·모델 목록 GET, 생성 아님).
  - 별도로, 일부러 잘못된 키로 한 생성 시도 1회는 사용자 키가 아니며 Google이 400으로 거절(서버 로그가 아닌 별도 프로세스).
  - 이후 비교 보고서·후속 조사·UI 작업에서 추가 호출 **0회**.
- 결과: `provider_mode=live`, "Gemini 해석" 배지, 데모 표시 없음, 응답 4~5.5초.
- 실제 학교 데이터 흐름: "금요일은 가능하면 비워 줘. 월요일 오전 9시부터 10시 15분까지는 수업이 없으면 좋겠어." → 금요일 공강(가능하면) 추가 가능, 시간대 회피는 모델이 종료 시각을 null로 반환 → **미해결로 표시되어 추가 불가**(수정 효과 확인) → 버리고 확인 → `/solve` optimal 후보 3개, 3개 모두 금요일 공강 충족.
- 잘못된 키 실제 호출 → 502 `LLM_HTTP_ERROR`, 수동 입력 안내. 서버 로그에 키 문자열 없음.
- 일반 테스트·E2E는 mock/fixture(E2E 전용 백엔드 8010, `LLM_PROVIDER=fixture`)로 실행.
